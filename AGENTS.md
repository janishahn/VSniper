# VSniper: Agent Instructions

VSniper scans saved Vinted searches, judges listings against a learned taste profile with vision models, and sends strong matches to Telegram. It runs as one self-hosted container, down to a Raspberry Pi 4B. It is a fork of `jonas-klesen/VSniper`, which is the `upstream` remote.

## Project Rules

- Vinted support is limited to the `de` region. Do not add multi-region branches or fixtures.
- Routes and worker jobs stay thin; business logic lives in `src/vsniper/services/`. `AppState` (`core/state.py`) is a resource facade without business methods.
- Search runs are coordinated through database-backed claims. Do not add an in-process lock.
- The seven `ClothingItem` buckets (`schuhe`, `hosen`, `obenrum_warm`, `obenrum_mittel`, `obenrum_kalt`, `kopf`, `ringe`) carry through samples, observations, drafts, searches, candidates and feedback.
- Judgment scores are integers from 1 to 100. Feedback is evidence for the next taste recompute, not an immediate weight change. Web and Telegram feedback share one candidate-feedback path.
- `domain/contracts.py` is the wire contract; mirror changes in `ui/src/types.ts`. Persistence models stay internal, with conversions in services.
- Review every autogenerated Alembic migration's upgrade and downgrade before keeping it.
- Vinted parser changes need fixture-backed tests. Add or update a saved `de` fixture instead of weakening assertions.
- The UI calls the API only through `ui/src/lib/api.ts` with `/api/*` paths.

## Project Documents

- Before changing a prompt in `integrations/openai/client.py`, compare the current and revised prompt with `scripts/iter_prompts.py` (observation and taste) or `scripts/iter_judge.py` (judging). They call paid APIs and read local reference photos.
- Update `README.md` only when setup, behavior or commands change.
- Cut a release (a `v*` tag) only when asked; see `README.md`.

## Verification

- Run `uv run fast-tests` (Ruff, ty, pytest) for backend changes and `npm run build --prefix ui` for UI or contract changes.
